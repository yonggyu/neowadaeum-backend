## 1. 지금 결정해야 하는 것

### D-1. 탈퇴 파기가 도달률 통계를 되돌린다 — **해소 (2026-08-29, 이슈 #228)**

**C 안을 채택했다** — 파기 전에 집계에 반영하고 지운다. 근거와 규칙은 `docs/corrections.md` §13-44.

- **지운다** — `play_session` · `turn` · `game_state_snapshot` · `story_summary`. **파기의 범위를
  좁히지 않았다.**
- **남는다** — `purged_session_tally` 의 `(story_id, ending_id, reached_count)`. `player_ref` 도
  `session_id` 도 **플레이 시각도** 없다. 남는 문장은 *"이 작품의 이 엔딩에 몇 번 도달했다"* 하나다.
- 따라서 **탈퇴로 과거 작품의 도달률·표본이 줄지 않는다.**

R12.4 가 세션·턴에 *"삭제 **또는 익명화**"* 를 허용한 것이 근거다. 여기서는 둘 다 한다 — 원본은
삭제하고 통계 기여분만 익명화한다.

**약관 문구는 D-2 에 남아 있다.** 아래 문장이 드러나야 이 결정이 성립한다.

### D-2. 약관·개인정보처리방침 문구 확정

**코드는 이미 지운다. 문서가 그 값을 말하고 있어야 한다.** S-10 이 B-61 의 DoD 로
*"약관 문구와 파기 주기 일치 확인"* 을 적었고, **코드 쪽만 끝났다.**

| 무엇 | 코드가 지금 쓰는 값 | 설정 키 |
|---|---|---|
| 프롬프트·응답 원문 | 90일 | `app.retention.prompt-log-days` |
| 감사 로그 (관리자·열람) | 3년 | `app.retention.audit-log-years` |
| 무활동 세션 → 만료 | 90일 | `app.retention.session-idle-days` |
| 미리보기가 만든 작품 | 30일 | `app.retention.preview-story-days` |

**함께 명시해야 하는 것**

- **UGC 작성자 탈퇴 시 작품 처리** — R12.5 가 *"약관에 명시해야 한다"* 고 못박은 항목이다.
  현재 구현은 §13-9 기본 채택안: **공개 작품을 `unlisted` 로 내리고 작성자명을 익명화한다.
  지우지 않는다.** (근거: 작품에 매달린 세션·도달률은 작성자가 아니라 **플레이한 사람들의
  기록**이다.)
- **탈퇴 시 세션·턴은 삭제한다.** 동의 이력만 법정 기간 남는다 (R12.4).
- **개별 플레이 기록의 원본은 파기하되, 개인을 다시 식별할 수 없는 집계 통계는 유지한다**
  (§13-44, D-1). 이 문장이 없으면 도달률 유지가 근거를 잃는다 — 코드는 이미 이렇게 동작한다.
- **해외 provider 사용 시 개인정보 국외이전 기재** (R12.2). AI 페이로드에는 회원 식별정보가
  들어가지 않지만(I-3, R12.1), 기재 의무는 그것과 별개다.
- **작품 만들기 입력란에 사용자가 개인정보를 쓸 가능성** (R12.6).

### D-3. 배포 환경과 레지스트리 — **구조 확정 (2026-08-29, 이슈 #234)**

**초기 스테이징은 한 대다.** Kubernetes 로 넓히지 않는다 — 무중단 교체에 필요한 것은 인스턴스
둘이지 클러스터가 아니고, 한 번도 배포해 본 적이 없는 상태에서 운영 표면을 늘릴 이유가 없다.

| | |
|---|---|
| 레지스트리 | **GHCR** — 내장 `GITHUB_TOKEN`. 새 자격 증명을 만들지 않는다 (기존 채택안 유지) |
| 호스트 | **단일 staging host** |
| 앞단 | **Reverse Proxy** (blue ⇄ green 전환) |
| 앱 | **Spring Boot Blue/Green** |
| 데이터 | **PostgreSQL** 하나 · **Redis** 하나 |
| 프록시 뒤 IP 신뢰 | **신뢰된 프록시에서 온 전달 헤더만 신뢰한다** (§13-45). 목록 밖에서 온 헤더는 읽지 않는다 |

그림과 근거는 `docs/deployment.md` §5.

**아직 없는 것 — 실제 호스트·클라우드·주소·시크릿.** 임의로 만들지 않는다. 신뢰 프록시
주소도 환경이 생긴 뒤에 설정으로 들어간다 — 값 없이 키만 늘리면 `.env` 필수 키가 하나 늘어
**지금 부팅이 막힌다** (§7.3).

**실배포 1회는 지금 어떤 이슈도 들고 있지 않다.** 이 문서는 B-63 이슈(**#224**)가 그것을
들고 있다고 적어 두었지만, **#224 는 2026-08-29 에 닫혔다** — 닫으면서 DoD 의 *"스테이징
무중단 배포 1회 성공"* 을 취소선으로 지우고 **"이 레포에서 끝나지 않는 것"** 으로 분리했다.
그 판단 자체는 옳다. 호스트도 레지스트리 접근도 운영 DB 도 레포 밖이라 **레포 안의 작업으로는
닫을 수 없는 항목**이었다.

**그래서 남은 일에 추적자가 없다. 지금은 이 문단이 그 유일한 자리다.** 환경이 생기는 시점에
이슈를 새로 열고 §3 표에 올린다 — 없는 추적자를 있는 것처럼 적어 두면, 그 이슈를 열어 본
사람이 *"닫혔으니 끝났구나"* 로 읽는다.

**브랜치 보호 설정 주의** — `Release` 워크플로의 `image` 잡을 **필수 status check 로 등록하지
않는다.** 경로 필터가 걸려 대부분의 PR 에서 돌지 않고, 돌지 않은 체크는 통과하지도 실패하지도
않아 **그런 PR 이 영원히 대기한다.** 필수는 `CI` 의 세 잡뿐이다.

### D-4. `main` 을 언제 올릴 것인가 — **의미 확정 (2026-08-29, 이슈 #234)**

**`main` 머지는 공개가 아니다.** 브랜치는 여기까지고, 그 오른쪽은 행위다.

```
backend  →  dev  →  main(릴리스 후보)  →  staging 검증  →  production release
```

`Release` 워크플로는 **`v*` 태그로만** 게시한다 — 브랜치 머지가 어떤 배포도 부르지 않는다.
그 분리가 이미 코드에 있었는데 문서가 `main` = 공개로 읽히게 두어, **릴리스가 올라가지 못한
채 `main` 이 부트스트랩 시점에 멈춰 있었다.**

그 결과가 이슈 **#181** 이다 — `.github/workflows/` 가 기본 브랜치에 없어 nightly 가 한 번도
돌지 않았다. GitHub 은 `schedule` 과 `workflow_dispatch` 를 **기본 브랜치의 정의로만** 실행한다.
`main` 이 후보를 담는 자리가 되면 nightly 와 `Release` 워크플로가 그 위에서 실제로 검증된다.
`nightly.yml` 은 `ref: backend` 를 체크아웃하므로 **도는 코드는 여전히 `backend`** 다.

정본은 `docs/git-workflow.md` §8.2 · §8.7.

**남은 것은 실행이다** — `backend → dev → main` 승격 PR 두 건. 그것은 사람이 정한다.
**production 배포와 태그 발행은 이 정리에 포함되지 않는다.**

## 2. 런칭 전에 넣어야 하는 운영 값

**코드가 이 값들을 기다리고 있다.** 없으면 뜨지 않거나, 뜨고도 동작하지 않는다.

### 없으면 화면이 뜨지 않는 것

| 값 | 어디에 | 없으면 |
|---|---|---|
| `ai.notice` | `service_config` (DB) | **랜딩이 500 이다** — 의도된 설계다 (§13-27) |

§11 이 AI 사전 고지를 의무로 규정하고 R11.1 이 문구의 하드코딩을 금지하므로, **문구 없이 그 화면을
내보내지 않는 것**이 유일한 방법이었다. `service_config` 에는 **시드가 없다** — 운영에서 넣는다.

### 없으면 기능이 죽는 것

| 값 | 어디에 | 없으면 |
|---|---|---|
| `ai.providers.<이름>.models.safety` | 설정 | **모든 턴이 막힌다.** 판정 실패는 통과가 아니라 차단이다 (fail-closed, I-12) |
| `ai.provider.active` | 설정 | 등록된 어댑터가 정확히 하나일 때만 뜬다. 둘 이상이면 **부팅이 멈춘다** (I-14 — 서버가 임의로 고르지 않는다) |
| `ADMIN_ALLOWED_CIDR` | `.env` | **관리자 경로가 통째로 닫힌다** (S-4). 비어 있음을 "제한 없음"으로 읽지 않는다 |
| `.env` 26개 키 | `.env` | 하나라도 없으면 **부팅이 실패한다** (§7.3 — 기본값 패턴 금지). 목록은 `.env.example` |

### 비어 있어도 뜨지만, 비어 있으면 안 되는 것

| 값 | 어디에 | 상태 |
|---|---|---|
| 블록리스트 항목 | `blocklist_entry` (DB) | **마이그레이션에 넣지 않는다** (S-11 — 공개 레포에 적힌 블록리스트는 그대로 우회 목록이다). 운영에서 넣는다 |
| `ugc.review.sampling_rate` | `service_config` | 코드에 기본값이 있다. 운영 값으로 덮는다 |
| `ugc.report.suspend_threshold` | `service_config` | 위와 같다 |

> **값 자체를 이 레포에 적지 않는다.** 임계값과 판정 기준을 알면 그 아래로 관리할 수 있다
> (§13-12, S-11). 그래서 여기에는 **어디에 넣는지만** 적는다.

## 4. 내가 고른 기본 채택안 — 뒤집을 수 있다

원문에 값이 없어 **기본 채택안으로 진행하고 PR 본문에 명시한** 것들이다. 근거는 전부
`docs/corrections.md` 에 있다.

| 무엇 | 채택안 | 왜 |
|---|---|---|
| 미리보기 작품 보관 | **30일** | 원고(`story_draft`)는 그대로 남는다 — 미리보기는 그 **사본**이고 다시 부르면 된다. 세션 만료 90일과 근거가 다르므로 같은 값을 쓰지 않았다 |
| 탈퇴한 작성자의 공개 작품 | **`unlisted` 강등 + 익명화** | 지우면 **플레이한 사람들의 기록까지** 사라진다 |
| 탈퇴한 작성자의 검수 상태 | **건드리지 않는다** | 승인은 작품에 대한 판정이지 작성자에 대한 판정이 아니다. 되돌리면 다시 검수 큐에 올라 사람의 시간을 쓴다 |
| 탈퇴한 작성자의 미발행 원고 | **삭제** | 볼 사람이 없어진 비공개 저작물이다 |
| 탈퇴 유예 기간 | **없다 — 즉시 파기 대상** | 다음 배치 회차에 처리된다 |
| `user` 행 | **지우지 않는다** | 동의 이력이 그 행을 앵커로 삼고, 그것은 법정 기간 보관 대상이다 |
| 탈퇴 회원의 리프레시 | **재발급 시점에만 상태를 확인한다** | 리프레시 저장소는 두지 않는다는 §13 결정을 유지하면서 차단을 성립시킨다. 액세스 토큰이 짧아 차단은 그 수명 안에 성립한다 |
| 이미지 레지스트리 | **GHCR** | 새 자격 증명을 만들지 않는다 |
| 파기된 세션의 도달 몫 | **익명 집계로 옮기고 원본은 지운다** | 통계는 작품에 대한 사실이지 회원에 대한 사실이 아니다 (§13-44) |
| 초기 스테이징 | **단일 호스트 + 프록시 + Blue/Green** | 무중단 교체에 필요한 것은 인스턴스 둘이지 클러스터가 아니다 |
| `main` 의 의미 | **릴리스 후보 — 공개가 아니다** | 태그가 릴리스다. 붙여 읽으면 `main` 이 멈춘다 (#181) |

## 5. 알려진 공백

**해소** — `docs/deployment.md` §3 의 **0번 단계**로 `service_config.ai.notice` 선입력이 들어갔다.
§13-27 이 배포 절차에 요구했던 항목이며, 넣지 않고 배포하면 **랜딩이 500 이다.** 설계대로지만
절차서에 없으면 첫 배포에서 장애로 보인다.

**남은 것 (문서)** — 약관·개인정보처리방침 원문 (D-2). 코드가 쓰는 값은 전부 정해져 있고, 그
값을 말하는 문서가 아직 없다.

### 코드로 남은 미완 — 없다

**`UnsupportedOperationException` 을 던지던 자리가 남아 있지 않다.** 마지막 하나였던 마스킹
정책이 2026-08-31 에 채워졌다 (아래).

### 해소 — 마스킹 정책 (2026-08-31, 이슈 #242)

`safety/l2/CategoryPolicy` 가 `SafetyPolicy.MASK` 를 만나면 예외를 던졌다. 스텁으로 통과시키지
않은 것은 옳았지만(§0.2) 그 카테고리는 **닿을 수 있는 경로**였고, 판정기가 그것을 돌려주면
그 턴이 실패했다.

**가리는 것은 서버가 자리를 아는 것뿐이다** (§13-46).

- **1단(블록리스트) 탐지** — 가린 뒤 통과. 정규화 위치를 원문 위치로 되돌리는 대응이 L0
  precheck 안에 이미 있었고, 그것을 `common/support` 로 올려 두 계층이 같은 것을 쓴다
- **2단(의미 분류) 탐지** — 가리지 않는다. 분류기는 카테고리만 돌려주며(§13-21) **위치를 받는
  계약을 새로 만들지 않았다.** 결과를 폐기하고 재생성 1회, 다시 걸리면 차단이다
- **입력(L1)은 가리지 않고 거부한다** — §9.2 의 "UGC 입력은 차단". 이 규칙이 없으면 마스킹이
  붙는 순간 개인정보가 든 입력이 통과한다

**함께 드러난 것 — 이슈 #243.** L2 검수가 문단의 **화자 이름**을 보지 않는다. 모델이 만든
문자열이고 사용자에게 도달하는데 판정기에 넘어가지 않는다. 이 작업의 범위를 넓히지 않고 별도
이슈로 올렸다.

### 해소 — 실 Provider 초안 (2026-08-31, 이슈 #238)

`AnthropicStoryProvider` · `OllamaStoryProvider` 의 `draftOutline` 이 예외를 던져
`POST /api/v1/authoring/drafts/{id}/outline` 이 **결정론 Provider 에서만 동작했다.** 세 PR 로
채웠다 — 계약(#239) · Anthropic(#240) · Ollama(#241).

**초안의 출력 계약이 평문에서 JSON 이 됐다.** 첫 줄을 제목으로 자르던 방식은 결정론 Provider 가
자기가 쓴 것을 자기가 읽는 동안만 성립한다 — 실 모델에서는 제목의 줄바꿈 하나가 설명을 제목으로
만든다. **형태는 계약이고 개수는 아니다**: 모자란 초안은 그대로 돌려주고(기존 결정), 재요청은
형식 위반에만 1회 건다.
