# Provider 장애

> **한 턴을 살리는 것과 세션을 옮기는 것은 다르다** (ADR-0007).

## 징후

| 지표 | 무엇을 본다 |
|---|---|
| `ai.call{outcome=...}` | 실패 비율이 오른다 |
| `ai.call.fallback{from,to}` | **0이 아니면 지목된 provider 가 죽고 있다** |
| `ai.call.latency` | 상승. `ai.provider.timeout-ms`(25초)에 붙으면 곧 타임아웃이다 |
| `play.turn.outcome` | 실패 상태가 늘어난다 |

사용자에게 보이는 모습 — 턴이 오래 걸리다 실패하고, 같은 세션에서 반복 실패하면 **쿨다운**에 걸린다
(`RETRY_COOLDOWN`, R6.5). 그것은 장애의 결과이지 원인이 아니다.

## 확인 순서

1. **`ai.call.fallback` 이 도는가.**
   - 돈다 → 체인이 작동 중이다. **사용자는 답을 받고 있다.** 원인 provider를 확인하고 복구를 기다린다.
   - 안 돈다 → 체인에 대체 provider 가 없거나, 그것도 죽었다. 3번으로.
2. **어느 `purpose` 가 죽었는가** (`ai.call` 의 `purpose` 태그).
   - `safety` 만 죽었다면 **모든 턴이 막힌다.** 판정 실패는 통과가 아니라 차단이다 (fail-closed, I-12).
     이것은 "AI 가 느리다"가 아니라 **전면 장애**로 다뤄야 한다.
   - `turn` 만 죽었다면 생성이 멈춘다. 세이프티는 정상이다.
3. **provider 쪽인가 우리 쪽인가.** `ai.call.latency` 가 모든 provider 에서 동시에 오르면
   네트워크·DNS·아웃바운드 경로를 먼저 본다.

## 조치

**대체 provider 를 체인에 넣는다** — 등록 조건을 만족하면 자동으로 들어간다 (R3.7).

```
ai.providers.<이름>.api-key      + models.turn   (원격)
ai.providers.ollama.base-url     + models.turn   (로컬)
```

**지목 provider 를 바꾼다** — 코드 배포 없이 설정만 바꾼다 (R3.1, B-18).

```
ai.provider.active: <어댑터 이름>
```

- **비워 두면 등록된 어댑터가 정확히 하나일 때만 뜬다.** 둘 이상이면 부팅이 멈춘다 — 모호한 상태에서
  서버가 임의로 고르지 않는다 (I-14 — Provider 선택은 관리자 전용이다).
- **지목했는데 그 어댑터의 키·모델이 없으면 부팅이 멈춘다.** 바꾸기 전에 값을 먼저 넣는다.

**타임아웃은 함부로 늘리지 않는다.** `ai.provider.timeout-ms` 는 **재요청까지 포함한 생성 전체의
상한**이고 (§13-19), 서버 응답 예산 28초가 그 바깥에 있다 (§6.3). 늘리면 커넥션이 그만큼 오래 잡히고
**느려진 채로 살아 있는 상태**가 장애보다 오래간다.

## 하지 말아야 할 것

- **진행 중 세션의 `provider_id` 를 고쳐 쓰지 않는다.** fallback 은 그 값을 건드리지 않는다 (ADR-0007, I-4).
  세션은 자기가 어느 provider 로 시작했는지를 계속 알고 있어야 하고, **그 턴 하나가 다른 곳에서 돌았다는
  사실은 `ai_call_log.fallback_from` 에만** 남는다. 고쳐 쓰면 문체가 튄 이유를 나중에 설명할 수 없다.
- **`models.safety` 를 비워 두고 재기동하지 않는다.** 판정 호출이 실패하고, 그러면 **모든 턴이 막힌다.**
- **세이프티 판정을 생성 모델로 임시 대체하는 것은 설정의 선택이지 우회가 아니다.** 별개 판정기라는
  요건(I-12)은 구조가 강요하며, 판정을 건너뛰는 스위치는 존재하지 않는다 (I-2, I-13).

## 복구 뒤

- `ai.call.fallback` 이 0으로 돌아왔는지 확인한다.
- 장애 구간의 `ai_call_log` 는 그대로 남는다 (보관 90일, R12.4). 사후 분석은 그것으로 한다 —
  **읽는 경로는 감사 기록을 남긴다** (R12.3).
